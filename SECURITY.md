# Security Policy

## Reporting a vulnerability

Please do not disclose security vulnerabilities in a public issue.

Use GitHub's private vulnerability reporting for this repository when available. Include the affected component, reproduction steps, impact, and relevant logs without including secrets or personal information.

If private vulnerability reporting is unavailable, use the repository's private contact mechanism rather than posting sensitive details publicly.

## Safety-sensitive reports

For issues involving emergency information, medical interaction behavior, treatment-resource results, legal information, or privacy disclosures, identify the exact screen and behavior and include the source data or endpoint involved when possible.

If a report could cause immediate harm to users, treat it as safety-sensitive and avoid publishing exploit or failure details until a fix or mitigation is available.

## Supported versions

Security fixes are applied to the current default branch. Releases should be kept aligned with the supported Node.js major version documented in the repository.

## Scope

Security reports should cover the application, repository configuration, dependencies, client-side data handling, external-service integration, and release automation.
